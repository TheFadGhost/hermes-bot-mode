# Hermes Bot Mode

<!-- impeccable:product-schema 1 -->

## Platform

web

## Product Purpose

A private messenger for a nontechnical parent: one continuing chat per bot or group, with Chief ready to coordinate work. The September 17 Grok Bot recordings, screenshots and official iOS screenshots govern the simple desktop/mobile interface.

## Operating Context

React and TypeScript frontend, FastAPI backend, SQLite persistence, Telegram one-time sign-in, ChatGPT runtime connection, installed mobile web app support. Existing deployment is https://your-hermes-origin.example/bot/.

## Capabilities and Constraints

- Preserve authentication, real API calls, streamed messages, cancellation, approval controls, file tools, memory and computer management.
- Use real stored bots and conversations. Research screenshots and browser-test fixture data are evidence only, never production content.
- Groups with explicit @ mentions, bot creation/delegation and persisted daily/weekly routines are implemented. Email connectors and general voice input are not provided; do not imply they are connected.
- Keep original messages intact. Bound model context through scoped recent/archive retrieval and automatic compaction; avoid claims of perfect or literally infinite recall.
- Each bot keeps its own browser profile. Desktops start on demand, share capped execution capacity, and sleep when task/viewer leases expire. Manual computer ownership blocks bot actions.
- Bot names, instructions, avatar shapes and colors persist on the server.
- Physical iPhone behavior has not been verified; mobile browser layouts can be tested with emulation.

## Brand Commitments

The user explicitly requested Grok Bot's light desktop messenger and mobile app structure, colorful shaped bot avatars, a simple visual creator, restrained motion, and removal of generic AI dashboard styling. Retain Hermes as the existing app name. The attached images take priority over design-skill defaults.

## Evidence on Hand

User references, official App Store assets, documented product behavior and captured public pages live in design-research/desktop and design-research/mobile. Authenticated Grok access was unavailable. The website entry returned a Cloudflare barrier; public documentation rendered successfully.

## Accessibility

Keyboard access, visible focus, named icon controls, reduced-motion support, readable contrast and mobile touch controls are implementation requirements for this work.
